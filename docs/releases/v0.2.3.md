FlashGBLink 0.2.3

Delta writes are now checked on the cartridge instead of over the link.

Improvements
- Payload CRC32 command: `flash.py image` compares one CRC per sector instead of reading the image back (4 MiB diff in about 20 s instead of 2.5 minutes), and verifies a programmed sector with one CRC (about 0.5 s instead of 4.3 s).
- A full 4 MiB write with verification takes 2:51 (was 6:03).
- Repeat writes of an unchanged image take about a second and touch neither the link nor the cartridge.
- FlashGBX's "Skip writing matching ROM chunks" now works through the plugin (`CALC_CRC32`): all 32 sectors of an unchanged 4 MiB image are skipped in about 21 s (was 404 s).
- The delta state lives per profile and sector map under `~/.cache/flashgblink/delta`, probes every sector instead of the first 4 KiB, and is never recorded after `--no-verify`.
- A rejected block write re-erases and rewrites the sector instead of aborting the whole image.
- `flash.py read` splits long reads into link-sized commands.

Fixes
- The progress and completion screens preload a busy status while drawing, so a mid-draw reply can no longer confirm an update early and shift the next command by one word.

Compatibility
- Still works with upstream `nullstalgia/gbasend-rs`; the bundled Pico firmware is unchanged.
- For the experimental SO-paced line (3.6x faster reads), use the `performance` branch / 0.3.0b2.

Measured on the tested 32 MiB M36 bootleg cartridge with a 4 MiB Apotris image; see `docs/hardware-baseline.md` for the full numbers.
