**Experimental pre-release of the SO ready-line performance line, with a firmware
fix that makes the handshake reliable at higher clocks.** Plugin `0.3.0b3`;
`main` stays on 0.2.3.

`0.3.0b3` ships new Pico images from `tanweiken/gbasend-rs` `b68a37d`. The
handshake margins were 2 µs arm / 5 µs settle; on hardware the bridge then
clocked too soon once the clock reached the payload's own processing time, and
transfers above about 900 kHz came back mismatched. The margins are now 5 µs and
20 µs, which costs roughly 18 µs per word at a given clock but lets the handshake
run clean to 1.8 Mbaud.

## Speed test

`gbasend --speed-test` against the speed-test ROM, before and after the margin
change:

| Baud | Before | After |
|---|---|---|
| 900 kHz | 5,055 words/s | fixed delay (below the 1 Mbaud gate) |
| 1.0 MHz | mismatch | 9,727 words/s |
| 1.5 MHz | — | 10,831 words/s |
| 1.8 MHz | — | **11,071 words/s** |
| 1.9 MHz | — | mismatch (link limit here) |

The jump at 1 Mbaud is the probe locking on; the flat top is the speed-test
ROM's own per-word work, not the link. The 4 MiB numbers from `0.3.0b2` were
taken at 1.25 Mbaud with the old margins, so the end-to-end write is due a
re-measure at 1.5–1.8 Mbaud — the clock is now the lever.

## Install

All three parts have to come from this release — the payload, the plugin and the
firmware are a matched set:

1. **Flash the Pico** with `gbasend-pico.uf2` below (or `gbasend-pico-rgb.uf2`
   for a board with a WS2812 LED on GP16). Hold BOOTSEL, copy to `RPI-RP2`.
   Flashing over 0.3.0b2 is enough; the payload and host code are unchanged.
2. **Install the plugin**: extract `FlashGBLink-plugin.zip` below into
   FlashGBX's `plugins/` directory. It already contains the matching GBA
   payload.
3. **Build `gbasend`** from <https://github.com/tanweiken/gbasend-rs> at commit
   `b68a37d`. Upstream `nullstalgia/gbasend-rs` does not carry the handshake, so
   its nootloader and speed test do not match this firmware.

## Compatibility

- `main` (0.2.3) and upstream `gbasend` are unaffected; do not mix a payload
  from one line with firmware from the other.
- The handshake only engages at or above 1 Mbaud. The BIOS multiboot upload
  (256 kHz), a session opened below 1 Mbaud, and an older payload all keep the
  fixed delay, so mixed installs stay safe but get no speedup.
- Validated on the M36 cartridge above only; other profiles are not yet tested.

## Not measured yet
