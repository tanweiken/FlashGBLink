FlashGBLink 0.2.4

Backups can be trusted, unsupported saves fail loudly, cancelling a write
leaves a clean device, and a second flash no longer inherits the completion
screen.

Improvements
- Checked reads: the payload adds `OP_CAPS`, `OP_READ_CHECK` and
  `OP_READ8_CHECK`. Every ROM, save, CFI and verification read carries a
  rolling checksum; a mismatch retries three times and persistent corruption
  raises instead of returning a suspect backup. An older payload keeps
  working with unchecked reads and a one-time warning.
- Save safety: `restore` requires a file that matches the save size exactly,
  EEPROM reads no longer return a plausible-looking blank backup, and
  `--save-type sram-32k|sram-64k|sram-128k` makes the size explicit.
- Cancellation: `OP_ABORT`, a CANCEL check between 4 KiB blocks in FlashGBX's
  WriteROM, and SIGINT handling between blocks/sectors in `flash.py image`.
  A cancelled write clears the delta state so the next run repairs the
  partially programmed sector.
- Unknown carts: a Burn2Slot-style scan tries six unlock layouts and six data
  wirings when no FlashGBX profile matches. `--fallback-write` is required to
  program a synthetic profile, and `--chip-erase` erases whole chips whose
  profiles have no usable sector map.
- `docs/cartridge-support.md` records detection, writing, save types, link
  integrity and the hardware-tested coverage. RTC data and EEPROM/save-flash
  media are explicitly unsupported rather than silently blank.
- The payload can now be built for the host (`-DPAYLOAD_SIM`) against a
  simulated cartridge and save bus; the new fault-injection, fallback,
  chip-erase, AMD polling and screen tests run in CI without hardware.

Fixes
- AMD buffered writes now poll the last word loaded into the write buffer and
  encode the buffer count as words minus one. This fixes writes to the
  ChisFlash 1.2 and other AMD-command-set carts, which previously timed out
  at the first programmed block.
- A status-register timeout is reported as `ST_TIMEOUT` and becomes a
  cartridge/programming error, not a protocol rejection. FlashGBX's own retry
  logic can re-erase and rewrite the sector instead of aborting with an
  "unresolvable error".
- Starting a second flash from the completion screen rebuilds the full
  progress layout, removing the leftover "FLASH COMPLETE", check mark and
  "RESTART GBA TO PLAY" text.

Compatibility
- Re-upload `payload/flasher.gba` to get checked reads and the AMD write
  fixes. The protocol reports version 1 and a read-check capability bit; an
  old payload falls back to unchecked reads with a warning.
- The Pico firmware is unchanged; no BOOTSEL update is needed.
- Still works with upstream `nullstalgia/gbasend-rs`.
- For the experimental SO-paced line, use the `performance` branch / 0.3.0b2.

Tests: 98 pass with `python3 -m unittest discover -s tests -t .`.
